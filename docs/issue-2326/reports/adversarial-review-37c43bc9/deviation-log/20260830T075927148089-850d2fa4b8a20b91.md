Methodology swap, not a scope change: the first attempt at re-deriving PR #2866's timing claim used
`git worktree add /tmp/pr2866-verify FETCH_HEAD` (against this session's own repo) rather than a plain
`git clone`. That worktree checkout happened to sit directly under an unrelated, pre-existing empty
`/tmp/.git` directory left over from other testing on this shared machine. The hook's git-root walk
(`os.path.isdir(<probe>/.git)`) never recognizes a worktree's own `.git` file, so it walked past the
worktree's real root and latched onto `/tmp/.git` instead — every hook invocation against that checkout
silently reported nothing (0.1s, empty output) instead of the traced episode's real failing tests.

canonical: this session's own `bash -x` trace of that first checkout's hook invocation, plus a manual
`posixpath`/`os.path.isdir` walk run this session, both showing the walk terminating at `/tmp/.git`
(a directory, empty, unrelated to this repo) instead of the worktree's own root.

Switched to plain `git clone` checkouts for every subsequent timing and invariant re-derivation in this
round, and separately built a controlled, non-accidental repro of the same defect class (an outer real
repo containing an unrelated inner repo added as a worktree) to confirm the mechanism rather than rely
on the accidental trigger.
