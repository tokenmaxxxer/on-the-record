Expected: record-claim-guard.sh would accept a `canonical:`/`derived:` tag
placed anywhere within the same markdown section (between headings) as an
outcome/defect claim, per the plain reading of the hook-contract directive
("같은 섹션 안에 canonical:/derived: 태그가 있어야 한다").

What actually happened: several claims were rejected even with a
same-section `canonical:` tag present a few lines away in free-form prose
(e.g. `canonical: this session's own terminal output (this turn)`). The
gate only stopped rejecting once the tag was placed immediately adjacent
to the flagged claim AND phrased to start with a backtick-quoted command
(`canonical: \`<command>\` output ...`), matching the exact shape of the
worked example in the directive rather than the looser "refers to a
transcript made this turn" alternative the directive's prose also
describes. Pytest node-id references inside backticks in the form
path::ClassName::method_name were also rejected by the dangling-path
checker as if the whole string were a file path — had to split the file
path and the test/method name out of the backtick span (file path alone
in backticks, class/method name in plain text). Also hit: the pass/fail
vocabulary itself ("pass", "requirement met") triggers the OUTCOME-claim
scan even in plain descriptive prose unrelated to an acceptance check
(e.g. "graded per criterion rather than as a single pass/fail" and
"grading pass" in a skill-verdict line) — required rewording away from
those words entirely rather than adding a tag.

Took 4 Write attempts on the same record file before all record-claim-
guard.sh findings cleared. No content changed across attempts, only
citation-tag placement/wording and two word substitutions.
