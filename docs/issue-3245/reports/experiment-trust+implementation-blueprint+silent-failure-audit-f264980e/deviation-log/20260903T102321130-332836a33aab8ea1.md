"result":"Done."` (exit 0)

Expected (round 1's own claim, PR #3251's report frontmatter `verdict:`
and "Open findings" #1): CLI 2.1.259 does not fire plugin hooks in
headless mode on this machine at all, an environment-wide regression
blocking every `spawn.py --skills` dispatch, unrelated to the on/off
manipulation.

What actually happened instead: independent-verification-1 reproduced
`spawn.py doctor` succeeding twice under this session's own normal
environment on the identical CLI version, directly contradicting "blocks
every dispatch on this machine right now," and traced the real failure
to `prepare_arms.py`'s fresh, empty `tempfile.mkdtemp()` HOME (issue
#3183/PR #3185) carrying no OAuth credential state at all -- the
dispatched `claude -p` process fails immediately on "Not logged in",
which `doctor()`'s coarse `fired_ups and fired_pre` check cannot
distinguish from genuine hook silence, producing the same misleading
"훅이 headless 에서 발화하지 않는다" stderr text either way. This
session confirmed the mechanism directly (citation above): seeding only
`~/.claude/.credentials.json` into an otherwise-empty, freshly created
HOME is sufficient for `claude -p` to authenticate and run a real turn.

Consequence for this issue's deliverable: round 1's causal claim (an
external, unfixable-from-this-repo CLI regression) was wrong, and its
stated next step ("this session has no path to a different CLI version")
pointed at the wrong remedy. The actual fix is inside this project's own
reach and narrow: `scripts/consumer-path/run_pair.py`'s
`seed_arm_credentials()` copies this launcher's own operator credential,
byte-identical, into both arms' isolated HOMEs before dispatch --
touching neither `HOME` nor `MUSTER_SKILL_REPO` (the only two variables
`verify_manipulation.py` cross-checks against the manifest), so nothing
PR #3185 established as forgeable is reintroduced. Full detail,
including why HOME isolation was never actually load-bearing for skill
reachability (that is gated by the `--plugin-dir` argv flag, built from
`MUSTER_SKILL_REPO`, not by anything under `HOME`), is in this round's
own record and in the correction appended to PR #3251's original report.
