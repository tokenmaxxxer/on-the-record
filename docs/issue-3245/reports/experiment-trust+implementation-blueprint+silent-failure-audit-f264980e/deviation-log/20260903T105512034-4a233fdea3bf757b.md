canonical: this session's own dispatch attempt (pair `01-study-groups`
retry, after the `watch --session` fix), the crash traceback it produced,
quoted below

```
File "scripts/consumer-path/run_pair.py", line 446, in _P
    skill_name = skill_name
NameError: name 'skill_name' is not defined
```

Expected: with the `watch --session` fix applied, both arms of pair
`01-study-groups` to reach `watched-to-completion` and `run_pair()` to
proceed to H1/H2 scoring.

What actually happened instead: both arms DID reach
`watched-to-completion` this time (progress -- confirms the credential
and watch-session fixes both hold), but `run_pair()` itself crashed with
an unhandled `NameError` in a pre-existing code path
(`class _P: skill_name = skill_name`, present since PR #3251's original
commit `94a785f9`, never exercised before this session because no prior
attempt had both arms succeed) -- a class body assigning to a name also
read on the same line is scoped to the class namespace, not the
enclosing function, so the right-hand side `skill_name` is unbound.
Fixed by removing the self-referential shim and resolving each arm's
real session name independently (see below).

A second, related pre-existing bug surfaced investigating this:
`rcp.arm_workspace_dir()` and `rcp._default_deliverable_fetcher()`
(and this module's own `collect_verification_rounds()`) all construct a
path/branch as `issue-<n>/<skill_name>` (bare), the same wrong assumption
`watch --session` made -- every `--skills` dispatch always appends a
lease-disambiguator suffix, so none of these would have found the real
workspace/PR even once the `_P` crash was fixed.

Consequence for this issue's deliverable: fixed all three sites by
adding `find_pr_branch()` (prefix-matches `gh pr list` against
`issue-<n>/`, returns the most recently created match) and using its
result -- not the bare skill name -- to resolve each arm's workspace
directory and to fetch each arm's deliverable/verification-rounds
directly via the discovered branch. `silent-failure-audit` was re-applied
to the new code: `scripts/lint/silent_failure.py` (issue #3228's lint,
merged after this launcher was first written) flagged two pre-existing
subprocess calls in `execute_arm()` (`lint`, `dispatch`) with no
timeout, now given `timeout=60`/`timeout=120` with `TimeoutExpired`
handling, and two intentional None-collapses in `find_pr_branch()`/
`_fetch()` (gh failure vs. genuinely-no-PR use the same sentinel),
annotated `# silent-failure: allow` with the reasoning (every caller
already treats both as one "missing signal" case).
