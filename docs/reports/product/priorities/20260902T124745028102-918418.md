- 2026-09-02: independent verification of PR #3169's squash-collapse
  fallback for `scripts/issue-3127/verify_preregistration.py` found the
  fallback's trust root is Incorrect (angle 1 of this session's task):
  `verification_pr:` is checked only for "does the referenced PR have
  the two paths in the right order somewhere in its own history," never
  for "is the referenced PR the actual origin of the commit under
  review." A fabricated same-commit collision pinned at any unrelated,
  legitimate PR with the right internal order passes — reproduced live
  (`/tmp/attack1_unrelated_pin.py`, `ok=True`). This gap was already
  self-disclosed by PR #3169's own author as an out-of-scope "Open
  finding," not hidden, but it is unfixed on that branch as of this
  entry. General lesson for any future check in this repo that lets a
  PR/commit number recorded in working-tree content stand in for
  git-native ancestry after a squash-merge collapses the ancestry a
  check depended on: the pin must be bound to the specific commit under
  review (e.g. requiring that commit to equal or descend from one of
  the referenced PR's own commits), not merely resolved in isolation --
  otherwise the pin is attacker-controlled trust with no link back to
  what it is supposedly vouching for. Source: this session's own task
  brief and findings, docs/issue-3127/reports/experiment-trust+
  adversarial-review+silent-failure-audit-760379f7.md.
