A verification of a measurement harness must judge whether the harness
would produce a valid measurement if actually run, not only whether its
literal acceptance checks pass — "a harness that runs but measures the
wrong thing is worse than one that refuses" (verbatim framing from this
session's own spawning instructions). Concretely for this line of work
(issue #3127, the consumer-path skills-on/skills-off measurement): a
pre-registration's numeric threshold and sample size must come with a
stated power/effect-size number whenever a null is reported, per the
issue's own must-not clause, and this was checked as its own criterion
separate from the three literal acceptance checks.
