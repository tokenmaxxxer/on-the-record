- 2026-08-30: from PR #2824's CHANGES round (issue #2795): `plumbing._run_net()`'s
  bounded-timeout primitive is correct for spawn/pipeline call sites (a
  single session/attempt should halt on a stalled remote, issue #285 P5)
  but its fail-closed mechanism is `sys.exit()`, which is wrong for a
  network call made from inside a long-lived polling loop like
  `roster_watchdog()` — an uncaught `sys.exit()` there kills monitoring
  for the entire roster over one session's stalled remote, not just the
  one check. `board.py`'s `_remote_branch_head()` (issue #2795's
  remote-aware unpushed-commit check) now wraps its `_run_net()` call in
  `try/except SystemExit: return None`, folding a timeout into the
  function's existing "query failed" sentinel rather than letting the
  exit propagate. Future sessions adding a new network git call to any
  per-tick/per-roster-entry loop (watchdog, board, reconcile sweeps)
  should route through `_run_net()` for the timeout bound but must decide
  explicitly whether that call site can tolerate `sys.exit()` — if it
  runs inside a loop over multiple independent items rather than gating
  a single item's own progress, it almost certainly cannot, and needs
  the same `except SystemExit:` wrap converting the timeout into a
  per-item "unknown" result instead of a process-wide kill.
