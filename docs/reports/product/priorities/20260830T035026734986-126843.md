- 2026-08-30: standing measurement-discipline principle stated in issue
  #2837's body, generalizing beyond that one issue: before classifying a
  wait as pipeline latency (a defect worth optimizing), ask whether
  anything was actually supposed to dispatch the work during that wait —
  "a queue that waits because nobody requested the work is not slow."
  Applied concretely in this issue's record (#2787's 336-minute wait was
  confirmed, via `runs/spawn-attempts.jsonl`, to have zero prior dispatch
  attempts on record — backlog wait, not a pipeline defect). Future
  latency-measurement issues in this repo should check dispatch-attempt
  history before attributing an idle gap to the pipeline itself, not just
  measure the gap's duration.
- 2026-08-30: companion principle, also from issue #2837's body: "An
  honest 'not derivable from current data' is worth more here than a
  plausible number." Applied in this issue's record by reporting the
  within-session record/PR-body/landing vs editing/testing split as only
  partially derivable (n=2, heuristic gap-attribution, and explicit about
  what instrumentation would be needed to go further) rather than
  presenting it as a clean, fully-instrumented result. Future measurement
  records in this repo should prefer a scoped, caveated partial answer
  over a plausible-looking one built past what the data actually
  supports. Source: docs/issue-2837/reports/diagnose-first-9f2f8297.md.
