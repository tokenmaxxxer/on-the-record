The round-3 spawning prompt stated two standing principles, specific to this codebase's automatic (non-interactive) git-network calls, while scoping this round to closing the credential-prompt gap in `skills.py`'s SessionStart skill-repository clone:

1. **"Nothing here may hang a session start."** Any git-network call this codebase makes automatically (SessionStart hooks, background sync/fetch/clone paths) must fail closed rather than block indefinitely — a credential prompt or unreachable remote must convert into a bounded, actionable error, never an unbounded wait on a session a human is sitting in front of. Demonstrated this round: `skills._skill_repo_git_env()` (`GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS=true`, applied unconditionally, no `GH_TOKEN` gate) closes the credential-prompt case; `plumbing._run_net()`'s pre-existing `timeout=` bound covers the separate TCP-blackhole case. canonical: `git show FETCH_HEAD:docs/issue-3231/reports/implementation-blueprint+silent-failure-audit-43f2f6d1.md` (FETCH_HEAD = `d1573e71`, PR #3235 branch, read this session), "Demonstration 1" and "Demonstration 2" sections.
2. **"Demonstrate rather than assert."** A claim that a fail-closed fix actually converts a hang into a bounded error must be backed by a captured transcript of the failure mode occurring and then not occurring, not a description of the code alone. The round-3 record's own first attempt at this illustrates the trap: a `script(1)`-based repro gave a false pass (looked like the fix worked, but the sandbox's non-tty stdin made the *unfixed* code path exit fast too, for an unrelated reason) — only a `pty.openpty()`-based repro that forced a real blocking read actually distinguished before/after. canonical: same source as above, "What did not work" section.

Neither principle was found already captured under `docs/reports/product/` for issue #3231 (checked via `grep -rli` across `docs/reports/product/` for "hang", "credential.prompt", "session.start", "fail-closed", "demonstrate" before adding this entry, this session) — this is the first capture of both for this issue.
