canonical: this session's own spawning prompt (issue #2920 round 2 task text), read at session start.

The operator stated a standing rule for judging whether a retired-word-bearing identifier (e.g. one containing "role" after the role→skill axis was retired) may be kept rather than renamed: a test (or other code) "whose whole purpose is to assert that a retired [word] no longer [does the retired thing] arguably must name that retired [word], which is the same trade the project already accepts for a proper-noun historical citation of a named contract (precedent core#361) — but a persisted key or a runtime-compared string is NOT that trade." Concretely: an identifier that exists purely as prose for a human/test-runner reader, and that cites a *specific* named contract by its own identity (a gate file's self-exclusion, a decision doc's own reference number), may keep the retired word. An identifier whose value is written to storage, compared at runtime against caller input, or otherwise participates in behavior — or that merely *describes a general concept* in English rather than naming one specific contract — does not get that exemption and should be renamed instead.

Applied this session to `test_retired_role_name_no_longer_pulls_in_family_members` (issue #2920): the function name is not a persisted key or runtime-compared string, but it also does not cite one specific named contract (it describes the general concept "a retired role name" in prose form) — so it was renamed to `test_retired_family_prefix_no_longer_pulls_in_family_members` rather than kept and justified.

Future sessions judging whether to keep or rename a retired-axis-bearing identifier (anywhere a naming/word retirement is being enforced, not just this issue's role axis) should apply this same two-part test: (1) is the identifier's role purely descriptive/citational rather than data-carrying, and (2) does it name one specific contract by identity, not just describe the retired concept generally. Both must hold for the exemption; either failing means rename.
