  cost/ownership audit that partitions by *repository* is not the same
  partition as by *ownership* — `tokenmaxxxer-core` and `warrant` are
  separate GitHub repositories from on-the-record, but they are the same
  team's plugins, so tokens they inject count toward "what we own" even
  though they live outside on-the-record's own tree. The prior round
  (PR #2851, independently verified by PR #2856) measured everything
  correctly and still reached the wrong conclusion (8-10% actionable,
  ending the diet) because the issue itself was framed on the
  per-repository line. Same failure shape as #2720's axis mismatch, in a
  new place: a well-posed question inside a wrong frame gets a good,
  faithfully-measured, useless answer, and the gap is invisible to every
  session working inside that frame (verification included) because
  verification checks the arithmetic, not the frame the arithmetic was
  posed in. Future cost/ownership audits in this program should state
  the ownership line explicitly (team-owned repos, not just the repo
  under audit) before measuring, not after a first round closes on the
  wrong number.
