The spawner stated principles specific to reporting a partial or failed
paired-experiment measurement honestly, rather than smoothing it into a
clean-looking result:

1. **A pair failing its manipulation-check gate (H1) is excluded from H2
   with the reason recorded — never silently reported alongside an H2
   figure.** If every registered pair fails H1, the required report is
   "not measured, manipulation check failed" with the actual directive
   bytes, explicitly named as a repeat of issue #3053's retracted
   zero-mount run, not a null result.

2. **A null result still requires a power statement for the achieved
   sample size.** "Not measured" is not license to omit what the achieved
   n could or could not have resolved — the spawner's own framing (issue
   #3053) treats an unstated power claim as itself a defect.

3. **Do not drop an arm or pair because it went badly.** A failed or
   partial arm's real data (wall-clock, cost, deliverable) must still be
   reported per-arm even when the pair as a whole cannot produce a paired
   comparison — "it went badly" is not grounds for omission.

4. **Do not standardise away the orchestrator's skill choices.** The
   skill/task/pair identity registered in the pre-registration is fixed;
   a session executing the measurement does not substitute a
   better-behaved skill or task to make the run succeed.
