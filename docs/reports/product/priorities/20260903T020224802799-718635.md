Two standing priorities stated for this round, generalizable beyond this
one issue:

**A guard belongs with the mechanism it protects, not with the one
caller that happens to trigger it today.** Quote: "Close it anyway,
since 'not reachable today' is a property of one call site and the
guard belongs with the mechanism." Applied this session: the SSH
passphrase gap was closed in `_skill_repo_git_env()` itself (the shared
mechanism), not only in the one call site (`skills.py:136`'s hardcoded
`https://` URL) that happens to be unreachable via SSH today.

**A sweep claim must be corrected visibly, not edited away, when it
turns out wrong.** Quote: "Correct the record's sweep claim visibly
rather than editing it away. A record that says a sweep found nothing,
when it missed three sites, is the reporting defect this repo has spent
two days removing." Applied this session: round 3's "sweep found
nothing else" claim, already known wrong from PR #3256's verification,
was found wrong *again* by this session's own re-sweep (~20 more sites)
-- recorded as a correction with the full list, not silently absorbed
into "now it's fixed."
