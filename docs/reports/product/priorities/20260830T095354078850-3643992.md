2026-08-30 — issue #2876 round 2 (JiwonJung94, round-2 spawn note quoted in docs/issue-2876/reports/silent-failure-audit-b01a1db4.md): a check's own supporting methodology (the ad-hoc searches used to audit/dispose what the check finds) can carry the identical coverage-blind-spot defect as the check itself, and nothing catches that recursion automatically — PR #2881's reader-accounting grep for "who reads this key" was hand-typed `--include=*.py`, which is exactly the kind of narrow, retyped-by-hand scope the retirement check itself was built to stop relying on. Priority: when a check derives its own file population via a function (e.g. `tracked_sources()`), expose that population for reuse (a `--list-files`-style mode) so every later ad-hoc search pipes through the checker's own declared coverage instead of restating an independent guess at the same boundary — a search that can silently narrow below what the checker covers is the same failure mode as the checker itself, one level up. canonical: docs/issue-2876/reports/silent-failure-audit-b01a1db4.md, "Why" section, "The reader-check's own blind spot was the same shape as the bug it was hunting".
