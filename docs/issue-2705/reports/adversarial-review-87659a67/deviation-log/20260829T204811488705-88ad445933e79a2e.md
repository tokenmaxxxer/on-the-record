Probe-construction correction mid-review: the first attempt to test
`cd -`'s toggle semantics in isolation used
`cd sub && cd sub2 && cd - && cd -` against a scratch clone where `sub2`
was a sibling of `sub`, not a child of it — so the second segment
(`cd sub2`, evaluated relative to the now-current `sub`) was itself a
`cd` to a nonexistent target, not a valid probe of `cd -`.

derived: running the identical command under real bash first (this
session) showed the `&&` chain aborts at the failed `cd sub2` either
way, so the guard's `RC=0` on this command was a restatement of the
already-acknowledged nonexistent-`cd`-target-under-`&&` coincidental
match (documented by both merged prior verification records for this
same file), not a new `cd -` finding. Caught before citing it as a
bypass by re-deriving the real-bash ground truth first, per this
session's own `defect-verification-independence-from-upstream-verdicts`
skill call.

Resolution: re-ran the intended question with a layout where every `cd`
target genuinely exists (`cd sub && cd .. && cd - && cd -`, which lands
back at the repo root in both real bash and the guard's model), and
confirmed no bug in `cd -`'s toggle semantics — quoted in full in this
session's own record, `docs/issue-2705/reports/adversarial-review-87659a67.md`,
under "What was done" §1 and under "What did not work".
