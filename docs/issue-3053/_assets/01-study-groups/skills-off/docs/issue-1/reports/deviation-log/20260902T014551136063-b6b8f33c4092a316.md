# Deviation — orchestrator killed a running session

actor: orchestrator
issue: 1
when: 2026-09-02T01:45Z

## What was deviated from

The orchestrator does not interfere with a running spawned session. It watches,
reports, and lets the session reach its own terminal state.

## What was done instead

Killed pid 1262214, the second session spawned for slug
`research-evidence-discipline+user-discovery-evidence-strength-tagging-1ae594fd`
on `JiwonJung94/study-companion` issue 1.

## Why

The first session for that slug had already completed the correction round: four
citation fixes verified against primary sources, two commits, pushed, PR #2 head
moved to `9bac92e`. The harness classified that outcome `failed-no-commit`, and a
second session was spawned on the strength of that classification.

The second session was re-doing landed work from the uncorrected original. Left to
finish, it would have produced a second corrected sibling file — a third copy of
the same report inside one PR — because board-gate's ownership rule turns a rerun
into a duplicate rather than an overwrite.

Letting it run to its own terminal state was the alternative, and it costs a
compounding artifact in a consumer repo. Stopping it costs nothing already earned:
the first session's work is on the remote and was verified there before the kill.
