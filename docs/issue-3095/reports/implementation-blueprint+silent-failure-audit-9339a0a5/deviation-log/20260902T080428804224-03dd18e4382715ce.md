# Deviation: record draft refused twice by record-claim-guard's orphaned-path check

Expected the session record to be accepted by the write hook on the
first attempt, citing PR #3106's own files by backtick path — they are
real, git-tracked files, just not present in this session's own branch
checkout (they live on PR #3106's branch). Two Edit attempts were
refused instead — derived: the Edit tool calls themselves in this
session's transcript — result each time: `PreToolUse:Edit hook error
... record-claim-guard: 레코드가 존재하지 않는 경로를 참조한다 (issue
#330)`, naming `tests/test_spawn_on_pr_repo_scope.py` (untracked in
this branch), `gates/probe_parked_report_repo_leak.py` (untracked in
this branch), and
`docs/issue-3095/reports/implementation-blueprint+silent-failure-audit+test-derivation-0cae2f1d.md`
(untracked in this branch).

Cause, read from `orphaned_path_reference_check` in
`gates/record_lint.py`: the check tests literal on-disk existence in
the current working tree, not `git log --all` reachability, and its
"untracked"-narration exemption only looks at the one line immediately
before/after the citation — a first fix attempt (a shared disclaimer
sentence a few lines above several citations) still failed because
line-wrapping put the trigger phrase more than one line away from two
of the three citation lines.

Resolved by putting the recognized phrase `(untracked in this branch)`
directly on the same physical line as every backtick citation of a
PR-#3106-only path, instead of a shared lead-in sentence. Third Edit
attempt on the same file was accepted — derived: the same session's
Edit tool call — result: no hook error, file write confirmed. No change
to the record's substantive content — only where the narration phrase
sits relative to each citation.
