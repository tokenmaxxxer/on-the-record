## Deviation: landing sequence had to be split, and one PR-create attempt ran against an unpushed branch

Expected the landing-batching guidance (composite `git push && gh pr create ...`
in one call) to hold. It did not: the combined call used a heredoc
(`cat > /tmp/pr2961-body.md <<'BODYEOF' ... gh pr create --body-file ...`)
to author the PR body, and `heredoc-command-refusal-gate.sh` refused the
whole command because it contained a `<<` heredoc alongside a
`gh pr create` invocation — even though the actual `gh pr create` call
itself used `--body-file`, not an inline `--body "$(...)"`. Fixed by
writing the body with the `Write` tool instead of a shell heredoc, then
running `git push` and `gh pr create` as separate calls.

The first `gh pr create` attempt after that then failed with "No commits
between main and issue-2961/adversarial-review-fb462020" — the earlier
combined command had aborted (due to the heredoc refusal) before its
`git push` half ever ran, so the branch didn't actually exist on the
remote yet; the failure surfaced one step later, at `gh pr create`, not
at the point where the push silently didn't happen. Fixed by re-running
`git push -u origin issue-2961/adversarial-review-fb462020` explicitly.
derived: `git branch -vv` (checked right before the retry) — result: `* issue-2961/adversarial-review-fb462020 b2282237 [origin/main: 1개 앞] ...` (local branch 1 commit ahead of `origin/main`, no dedicated upstream tracking ref yet — confirming the earlier push never landed). The retried push and `gh pr create` both then succeeded (PR #2971).

No scope or content change resulted — this affected only the landing
mechanics, not the verification record itself.
