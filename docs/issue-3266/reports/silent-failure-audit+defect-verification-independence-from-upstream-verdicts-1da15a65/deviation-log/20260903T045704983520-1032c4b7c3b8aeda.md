Task instruction item 3 said: "run `spawn.py clean --dry-run` on the PR
head and on main back to back and report both". I did not run that literal
command on either ref.

Why: `derived:` `git show pr-3269-review:spawn.py | grep -n "a.dry_run"`
and the `clean` dispatch at `spawn.py:2935-2936` (`if a.role == "clean":
return roster_clean(_workspace_base(), a.issue, Path(a.cwd).resolve())`)
show `--dry-run` is a top-level argparse flag never read by the `clean`
role — it is silently accepted but has zero effect, so
`spawn.py clean --dry-run` performs real, irreversible `shutil.rmtree()`
deletions against `~/.tokenmaxxxer/work`, a shared directory with a
sibling verification session's workspace live in it at the time.

Swap: built a read-only re-derivation instead
(`/tmp/dryrun_probe.py`/`probe2.py`) that imports the real
`_sp._workspace_clean_state()` from a full worktree checkout of each ref
and tallies would-be-removed vs kept without ever calling
`_delete_workspace()`, then separately confirmed the finding itself (the
`--dry-run` no-op) via `git diff` rather than by demonstration, to avoid
causing the exact destructive action being investigated. Full derivation
and numbers are in the record's "What was done" section 3 and "Open
findings" item 4.
