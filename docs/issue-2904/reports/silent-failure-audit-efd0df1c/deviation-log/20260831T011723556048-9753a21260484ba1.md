# Deviations, issue-2904

derived: `git log --oneline issue-2904/silent-failure-audit-efd0df1c` and `docs/issue-2904/reports/silent-failure-audit-efd0df1c.md` (this session's own record, committed on this branch) — the three commits/parts below are cited from there.

1. **Self-audit found the queue's own write/read paths were silent-failure-shaped and fixed them mid-build, not as part of the original plan.** The first version of `_record_session_completion()`/`_drain_pending_completions()` let `open()`/`fcntl.flock()` raise `OSError` uncaught — invoking the mounted `silent-failure-audit` skill against this session's own new code (not just the target defect) surfaced that a disk hiccup on write would have aborted `_spawn_one()`'s completion tail, and a read failure would have returned `[]` indistinguishably from a genuinely empty queue — the same defect class issue #2904 is about, reproduced inside its own fix. Changed the write path to catch `OSError` and print an advisory instead of raising, and changed `_drain_pending_completions()`'s return type from `list[dict]` to `(entries, error)`.

2. **`git status --porcelain` needed `-uall`, discovered by a failing test, not anticipated in the initial design.** `test_record_file_touch_is_named_as_started` failed against the first draft of `_live_session_workspace_summary()`: a wholly-new untracked directory collapses to one `?? docs/` line under plain `--porcelain`, hiding the individual record file inside it. Added `-uall`.

3. **Scope widened twice by operator direction mid-session (issuecomment-5472355431, issuecomment-5472429696), each retained prior work rather than discarding it.** The first correction moved the subject from "the heartbeat should announce completions" to "the orchestrator must actively track what it spawned, including mid-flight before any PR exists, structurally, without opt-in" — added workspace-file tracking (Part 2) on top of the retained completion-signal fix (Part 1). The second correction found that Part 2's own git-status-only approach reproduced the issue's exact defect shape one layer down (file diff cannot distinguish active tool-call investigation from a stalled session when the same files are already dirty) — added tool-activity tracking read from the session's own transcript log (Part 3), using an absolute timestamp specifically because a relative-age rendering would have defeated the delta-suppression the whole design depends on.
