## Why

CORE_BUILD_NOW=1 (spawner-set) authorizes delivery-only per contract v3 s19a — no proposal round. Per survey-order.md, no alternatives survey either: both findings are bugfixes/corrections against a specific, already-adjudicated verifier report (two independent `verdict: fail` reviews, each with a live reproduction) — there was no open design question to survey, only "reproduce, fix, re-verify."

Prefix match (`HEALTHY-`) over an enumerated two-name set for the delta-diff fix: a set literal (`{"HEALTHY-CONFIRMED", "HEALTHY-UNCONFIRMED"}`) would reproduce the exact defect class this finding is about — it would again go stale, silently, the next time a `HEALTHY-*` state name is added or renamed. A prefix match degrades to "one more edit needed" only for a state that stops starting with `HEALTHY`, a far more visible kind of change than a same-prefix rename.

Calling the real `diagnose_health()` from the test fixture over inventing a second hardcoded literal: chosen specifically because the reported defect's root cause was exactly a hardcoded literal drifting out of sync with the real function — test-authoring-isolation-and-fixture-strategy rule 5.18 (real, fast, side-effect-free dependency preferred over a double) and the follow-up instruction's own diagnosis ("fix the fixture too so it exercises the real function, otherwise the same class of rename will slip through again") both point the same direction. Rejected alternative: leave the fixture on a corrected hardcoded literal (`"HEALTHY-UNCONFIRMED"`) — rejected because that only fixes today's instance and reintroduces the identical staleness risk against the next rename, which is the same finding restated, not resolved.

Record-correction over forced-gating for finding 2: see the Finding 2 bullets above for the full reasoning — restated briefly, gating `_self_trigger_respawn()` with `RESPAWN_CONSECUTIVE_CONFIRMATIONS` is not merely unnecessary but actively wrong, because the roster entry this path's key refers to is provably gone (synchronously removed) before a second observation could ever arrive, so the counter could never reach threshold and the feature it gates would never fire again.
