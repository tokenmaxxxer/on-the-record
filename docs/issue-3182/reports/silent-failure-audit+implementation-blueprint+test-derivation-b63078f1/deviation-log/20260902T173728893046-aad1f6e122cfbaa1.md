- Expected `_python_masked_spans()`'s multi-line-string span end column
  to be computable from the tokenizer's own `.line` attribute
  (`len(toks[0].line) + len(t.string)`). What actually happened: caught
  on inspection before ever running it that `toks[0]` is the `ENCODING`
  token, whose `.line` is empty, so the arithmetic was nonsense.
  Classified **inline-fix**: caught pre-execution, no test run ever
  exercised the broken version. Resolved by replacing it with a large
  sentinel column (`1_000_000`) and relying on Python slicing being a
  no-op past a string's length, needing no per-line length lookup.
  derived: this round's final
  `046f12b7ee7234812430f487ffeed7ede5aae3fd:tests/test_issue_3182_citation_line_accuracy.py`
  (on PR #3184's branch) has no `toks[0].line` reference; only the
  sentinel-column version was ever committed.

- Expected `test_statvfs_failure_reports_unsatisfied_naming_what_failed`
  to reproduce PR #3203's finding by patching only `os.statvfs` to
  raise. What actually happened: the test failed with `'inode' not
  found`, detail `'cannot read disk usage at ...'` — CPython's
  `shutil.disk_usage()` is itself implemented on top of `os.statvfs()`
  on POSIX, so patching `os.statvfs` alone also broke the
  `shutil.disk_usage()` call earlier in the same function, tripping its
  own except-OSError branch first. Classified **inline-fix**: no
  deliverable content changed, only the test's own mocking strategy.
  Resolved by also faking `shutil.disk_usage` to return a fixed
  ample-headroom value, decoupling it from the patched `os.statvfs`.
  derived: `python3 -m pytest tests/test_issue_3182_preflight.py -q -k
  statvfs_failure` (this round, on PR #3184's branch) — 1 passed, after
  the fix.
