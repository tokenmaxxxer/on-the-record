# Hunt record — pr2221-fixes

## before-landing — stance 0: assume the gate/guarantee just touched is bypassable — find a real input that breaks it.

Verdict: FINDING — `main()`'s "missing path is a hard, graceful CLI error" guarantee only checks `Path(args.session_log).exists()`, which is also True for a directory; passing a directory as `session_log` slips past the guard and then crashes with an unhandled `IsADirectoryError` traceback out of `parse_session_log()`'s `p.open()`, instead of the intended `error: session log not found: <path>` message on stderr.

### Reproduce
```
python3 trajectory_analyzer.py . 1>/tmp/out.txt 2>/tmp/err.txt; echo "EXIT=$?"
cat /tmp/out.txt
cat /tmp/err.txt
```

### Observed
```
EXIT=1
---STDOUT--- (empty)
---STDERR---
Traceback (most recent call last):
  File ".../trajectory_analyzer.py", line 455, in <module>
    sys.exit(main())
  File ".../trajectory_analyzer.py", line 449, in main
    report = analyze(path, include_raw_denials=args.include_raw_denials)
  File ".../trajectory_analyzer.py", line 388, in analyze
    events = parse_session_log(path)
  File ".../trajectory_analyzer.py", line 62, in parse_session_log
    with p.open("r", encoding="utf-8", errors="replace") as fh:
  File ".../pathlib.py", line 1119, in open
    return self._accessor.open(self, mode, buffering, encoding, errors,
IsADirectoryError: [Errno 21] Is a directory: '.'
```
The exit code (1) happens to be non-zero, so `test_cli_missing_path_exits_nonzero_with_clear_error`-style assertions on `rc != 0` alone wouldn't catch this, but this is a bare Python traceback, not the fix's designed error path — `path.exists()` is true for a directory, so the new guard's `if not path.exists()` branch is never taken, and control falls straight through into `analyze()` -> `parse_session_log()`, which unconditionally calls `p.open("r", ...)` and raises.

### Expected
Per Fix 1's stated contract ("a path that does not exist on disk is a distinct, explicit error here — non-zero exit, message on stderr — never the same all-zero report..."), any session_log argument that cannot actually be read as a session log file (missing, or existing-but-not-a-regular-file such as a directory) should hit the same graceful `error: session log not found: <path>` (or an equivalently explicit, non-traceback) message on stderr with a controlled exit code — not an uncaught `IsADirectoryError` traceback. The guard should check `path.is_file()` (or catch the `OSError` from `open()`), not bare `path.exists()`.
