# Deviation: skill-verdict line falsely claimed Skill-tool invocation

The record's original "Skill verdicts" section stated `skill-verdict:
work-in-english — applied: invoked; wrote this record, all commands, and
commit messages in English throughout`. The `invoked;` marker asserts an
actual Skill-tool call happened, per issue #2062's invoke-before-apply
rule.

canonical: Stop hook's skill-verdict-guard advisory, this turn — "this
session mounted 1 skill(s) (work-in-english) and invoked none of them via
the Skill tool." No `Skill({skill: "work-in-english"})` call appears
anywhere in this session's tool-call history.

The claim was wrong: the record was written in English by default (task
framing was Korean, output was English throughout regardless), not
because the skill was loaded and applied. Corrected to `other mounted
skills: not triggered`, since the skill-verdict-guard's own advisory
states no verdict line is owed for a mounted-but-never-invoked skill
(issue #2153's narrowing).

No re-landing of code was needed — this is a documentation-accuracy fix
to the already-pushed record, applied as a follow-up commit rather than
an amend per the completion-and-landing directive's "never amend, add a
new commit" rule.
