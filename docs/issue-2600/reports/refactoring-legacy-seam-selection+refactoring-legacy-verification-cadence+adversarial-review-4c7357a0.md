```
# /tmp/ast_scan.py — the exact script run for every "derived: python3 /tmp/ast_scan.py" citation in this record
import ast, pathlib, subprocess
files = subprocess.run(["git", "ls-files"], capture_output=True, text=True).stdout.splitlines()
files = [f for f in files if f.endswith(".py") and not f.startswith("docs/")]
hits = {}
for f in files:
    try:
        tree = ast.parse(pathlib.Path(f).read_text(encoding="utf-8"), filename=f)
    except Exception as e:
        print(f"PARSE-ERROR {f}: {e}"); continue
    names = set()
    for node in ast.walk(tree):
        if isinstance(node, ast.Name) and "role" in node.id.lower(): names.add(node.id)
        elif isinstance(node, ast.Attribute) and "role" in node.attr.lower(): names.add(node.attr)
        elif isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef)):
            if "role" in node.name.lower(): names.add(node.name)
            for a in node.args.args + node.args.posonlyargs + node.args.kwonlyargs:
                if "role" in a.arg.lower(): names.add(a.arg)
        elif isinstance(node, ast.arg) and "role" in node.arg.lower(): names.add(node.arg)
        elif isinstance(node, ast.ClassDef) and "role" in node.name.lower(): names.add(node.name)
    if names: hits[f] = sorted(names)
for f, names in sorted(hits.items()): print(f"{f}: {names}")
```

## Why

Kind-partitioned execution (env vars, comments/docstrings, prompt text, now identifiers, persisted keys still to come) was decided upstream of this slice, per the issue's own comment thread and #2720's post-mortem on partitioning by file-glob instead of by kind. Within this slice: (a) scope was derived from an AST walk rather than trusting the issue's own `\brole\b` acceptance regex as the work-list, because that regex is known (from slice 1's own record, reused here) to undercount compound identifiers — repeating exactly the #2720 defect (a kind-boundary miss disguised as a file-glob miss) was the single highest-priority failure mode to avoid; (b) execution used file-ownership-partitioned parallel workers (freelunch directive) rather than one long serial sweep, given the volume; (c) verification ran the fast full test suite (checked: `python3 -m pytest -m "not slow" -q` — result: 5-6s wall time each run) after every wave rather than per-file, since "immediate, risk-scoped, fast-first" (refactoring-legacy-verification-cadence) collapses to "just run the whole thing every time" when the whole thing is this cheap — no fast/slow split was needed; (d) every new test failure was treated as a stop-and-fix signal pointing at the identifier/consistency bug it revealed, never as a reason to adjust a test's expectations, except in the one class of case (golden literal-text-pinning tests whose pinned text needed updating to track an intentional, already-decided rename, `test/test_branch_role_field.py:99` below) where the "test" is a source-text mirror by explicit design, not a behavior characterization.
